# SLC-Clinic — ระบบจองหัตถการ & ติดตามคอร์ส

Web app prototype สำหรับคลินิกความงาม/เวชกรรม ที่แก้ปัญหาคลาสสิกของลูกค้า:
**"ซื้อคอร์สอะไรไปบ้าง ใช้ไปกี่ครั้ง เหลือเท่าไหร่ หมดอายุเมื่อไหร่"** — พร้อมจองคิวใช้สิทธิ์ได้ในแอปเดียว

ดีไซน์ **minimal / editorial** — ขาวสะอาด, การ์ดใหญ่ใบเดียวต่อคอร์ส, แถว "แสตมป์" โชว์จำนวนครั้งแบบอ่านปุ๊บรู้ปั๊บ, ฟอนต์ display (Kanit) + floating pill nav พร้อมปุ่ม **SCAN** เช็คอิน ใช้ **SVG icon ล้วน ไม่มี emoji**

> แนวคิด "แสตมป์": ช่องที่ประทับไอคอนแล้ว = ครั้งที่ใช้ไป, ช่องว่าง = ครั้งที่เหลือ — ตอบโจทย์ "เหลือกี่ครั้ง" โดยไม่ต้องอ่านตัวเลข

## วิธีเปิด

ไม่ต้อง build / ไม่ต้องลงอะไร — เปิด `index.html` ด้วยเบราว์เซอร์ได้เลย

```powershell
start clinic-care\index.html
```

> เปิดบนจอคอมจะเห็นเป็นกรอบมือถือ (mobile-first) — ลองย่อหน้าต่างหรือเปิดบนมือถือก็ได้

## ฟีเจอร์หลัก (5 แท็บ + flow ย่อย)

| หน้าจอ | ทำอะไรได้ |
|--------|-----------|
| **หน้าแรก** | การ์ดคอร์สใหญ่ใบเดียว (ปัดซ้าย-ขวาดูคอร์สอื่น) + แถวแสตมป์, นัดหมายถัดไปแบบบรรทัดเดียว — ข้อมูลน้อย เน้นอ่านง่าย |
| **คอร์สของฉัน** | ลิสต์คอร์สแบบเรียบ — เหลือ X/Y, แถบ progress บาง ๆ |
| **รายละเอียดคอร์ส** | การ์ดแสตมป์เต็ม + วันซื้อ/หมดอายุ/มูลค่าต่อครั้ง + ปุ่มจองใช้สิทธิ์ |
| **จองหัตถการ** | flow 3 ขั้น: เลือกบริการ → วัน-เวลา → ยืนยัน → ตัดสิทธิ์อัตโนมัติ |
| **นัดหมาย** | นัดที่กำลังจะถึง, QR เช็คอิน, ยกเลิกนัด |
| **ประวัติ / โปรไฟล์** | timeline การใช้บริการ, ข้อมูลสมาชิก, สถิติ |

**Navigation:** floating pill ด้านล่าง (หน้าแรก · คอร์ส · นัดหมาย) + ปุ่ม **SCAN** วงกลมดำสำหรับเช็คอินที่คลินิก · โปรไฟล์เข้าผ่านไอคอนมุมขวาบน

## โครงสร้างไฟล์

```
clinic-care/
├── index.html   โครงหน้า + กรอบอุปกรณ์ + status bar
├── styles.css   design system ทั้งหมด (custom CSS, ไม่พึ่ง framework)
├── icons.js     ชุด SVG icon (stroke) — ไม่มี emoji
├── data.js      ข้อมูลตัวอย่าง (USER / COURSES / APPOINTMENTS / HISTORY ...)
└── app.js       router + render ทุกหน้าจอ + ตรรกะการจอง
```

---

## การต่อยอดเป็นระบบจริง

โครงข้อมูลใน `data.js` ออกแบบให้ map กับฐานข้อมูลจริงได้ทันที:

- `COURSES` → ตาราง `customer_packages` (`total`, `used` → คำนวณ `remaining`)
- `APPOINTMENTS` → ตาราง `bookings` (FK ไปที่ `courseId` / `customerId`)
- `HISTORY` → ตาราง `package_usage` + `transactions`
- การยืนยันจอง (`confirm-book`) ทำ `used += 1` — ในระบบจริงคือ transaction ตัดสิทธิ์ + สร้าง booking

ขั้นถัดไปที่แนะนำ: เพิ่ม backend (เช่น Node/Express + PostgreSQL หรือ Supabase),
ระบบ auth, ฝั่ง **แอดมินคลินิก** (ออกคอร์ส/บันทึกการใช้สิทธิ์/จัดตารางแพทย์), และ LINE/SMS reminder
